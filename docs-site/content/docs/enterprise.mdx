`speckit-security` is free, open source, and covers the core security
gates for spec-driven development. **For teams shipping AI products
to regulated buyers**, an enterprise layer with additional runtime
and compliance features is in development.

## What the enterprise layer adds

- **Runtime middleware generators** — turn declared PII strategies
  and guardrail configs into real TypeScript middleware that every
  route imports, so the enforcement happens at runtime, not just at
  review time
- **Signed gate-log attestation** — cosign or ed25519 signatures on
  every gate verdict, producing a tamper-evident audit trail
  auditors can verify
- **Gate-log verification** — detect any tampering in the audit
  trail since the last signed checkpoint
- **SOC 2 preflight** — cross-walk a feature spec against the Trust
  Services Criteria points of focus and flag gaps before the feature
  reaches an audit
- **Compliance report generator** — single auditor-consumable
  document aggregating gate logs, red-team traces, ADRs, and spec
  metadata

## What it does NOT do

To be explicit:

- **It does not replace SOC 2 automation platforms** like Vanta,
  Drata, Secureframe, or Laika. Those are continuous-evidence-
  collection tools that pull from AWS, GitHub, Okta, HRIS, and
  hundreds of other integrations at the organization level.
- **The preflight catches spec-level gaps**, not runtime drift.
  It's a developer-time control, not a production-time control.
- **It's complementary**, not competitive. The typical workflow is:
  use Vanta for org-wide continuous compliance, use this for feature-
  level gap checks at design time so issues don't compound into
  audit findings later.
